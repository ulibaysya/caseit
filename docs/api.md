# Authentication

## Code

### `POST /auth/code/exchange`

#### Requests

```jsonc
// body
"0nwkpbSykWBYTCdem1sJDxtLIxv0B4VXq56D6VWXlD8="
```

#### Responses

```jsonc
// 200
{
    "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiYWRtaW4iOnRydWUsImlhdCI6MTUxNjIzOTAyMn0.KMUFsIDTnFmyG3nMiGM6H9FNFUROf3wh7SmqJp-QV30",
    "refresh": "eyJhbGciOiJFUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwiaWQiOjcxOTU4MjMsImlhdCI6MTc4Mzc2ODA0NH0.F1kdLRJ9hd9WlQfSO6yFfK6a7oUG67z2zL5ensSULk57hXTSXAWbFOwXVKsaSnPwzsKRIt9LmGZMmbDKaMqNIg"
}
```

#### Description

This endpoint accepts a code which can be generated by different methods
(authentication with external services, manual key login). After verifying
code, refresh and access JWTs are returned. With access token you can
access all other sections of the API. With refresh token you can generate new
access and refresh tokens.

Code can be associated with some user, then returned tokens are associated with
this user too. If code isn't associated with any user, then a new user is
created with data associated with code (external authentication providers
return name and image URL, manual key login can associate those too) and
returned tokens are associated with newly created user.

Each code becomes invalid after some expiration date (usually it is a short
period of time). Each code can be exchanged for tokens only once.

#### Parameters

##### Required

- `code`: code to exchange

## Keys

### `POST /auth/keys` 

#### Requests

```jsonc
// body
{
    "id": 7541982,
    "exp": 3376684800,
    "nbf": 2147483647
}
```

```jsonc
// body
{
    "name": "I AM NiCkNaMe",
    "img": "https://upload.wikimedia.org/wikipedia/commons/thumb/a/a8/NASA-Apollo8-Dec24-Earthrise.jpg/1280px-NASA-Apollo8-Dec24-Earthrise.jpg",
    "dur": 604800,
    "aft": 259200
}
```

#### Responses

```jsonc
// 201
"x9xcEYU0ZgAtrxohvpqVTubhH9gJIJBJlPBp8qIEqHA="
```

#### Description

Authorized.

This endpoint accepts a user ID and returns a key. This key can be exchanged
for code which will be associated with a user, which is associated with 
specified ID. You can specify not ID but parameters like name and image so
a user will be created when code is exchanged for tokens. By default
one-time key is created (`num` is `1`).

#### Parameters

##### Required

One of:

- `id`: user, associated with this ID, is associated with exchanged code. ID
  format

or

- `name`: name for new user. String format
- `img`: image for new user. Default is anonymous avatar. URL format

##### Optional

- `num`: number of usages for code. Use `0` to make unlimited number of usages.
  Default is `1`. Integer format

One of:

- `exp`: specifies a date after which key becomes invalid. Unix epoch format
  (seconds since jan 1 1970)
- `dur`: specifies a key's validity duration. Seconds format

Default is none (no expiration time).

One of:

- `nbf`: specifiec a date before which key is invalid. Must be greater than
  current date. Must be before exp/dur parameters if they are specified. Unix
  epoch format (seconds since jan 1 1970)
- `aft`: specifies a key invalidity duration. Must be greater than 0. Must be
  before exp/dur parameters if they are specified. Seconds format

Default is none (key is valid immediately).

### `POST /auth/keys/exchange`

#### Requests

```jsonc
// body
"lMfKMeOWWZXaPV_xsRSiY2kKnrZEkXtwTKv9DBj7J1g"
```

#### Responses

```jsonc
// 200
"Ev-NJ6iVNmh8H-ssxUfgIq-Ka6YYQo9fFWoZvihzngY"
```

#### Description

This endpoint accepts a key and returns a code which can be exchanged to JWTs.
Key's state is modified (number of usages, other parameters).

This endpoint returns an authentication provider URL. If `redirect` is set to
`true`, 302 Found is returned with `Location` set to authentication provider
URL. If there is a parameter to specify a URL to which authentication provider

https://{host}/auth/external/{external}/login/callback is specified.

This endpoint is intended to login unauthenticated users.

  authentication provider URL. Default is `false`. `true`/`false` format

### `GET /auth/external/{external}/login/callback`

#### Requests

```bash
# url
https://api.caseit.net/auth/external/steam/login/callback?state=YoD0ktm3ZmoZaEZg_Tj08qwyGtdMkjM8Vb4TkfvlyFA&openid.ns=http%3A%2F%2Fspecs.openid.net%2Fauth%2F2.0&openid.mode=id_res&openid.op_endpoint=https%3A%2F%2Fsteamcommunity.com%2Fopenid%2Flogin&openid.claimed_id=https%3A%2F%2Fsteamcommunity.com%2Fopenid%2Fid%2F76561199869581327&openid.identity=https%3A%2F%2Fsteamcommunity.com%2Fopenid%2Fid%2F76561199869581327&openid.return_to=https%3A%2F%2Fapi.caseit.net%2Fauth%2Fexternal%2Fsteam%2Flogin%2Fcallback%3Fstate%3DYoD0ktm3ZmoZaEZg_Tj08qwyGtdMkjM8Vb4TkfvlyFA&openid.response_nonce=2026-07-11T19%3A24%3A53ZeFalPSYlOEvoxCq4qb9rO1YND10%3D&openid.assoc_handle=1234567890&openid.signed=signed%2Cop_endpoint%2Cclaimed_id%2Cidentity%2Creturn_to%2Cresponse_nonce%2Cassoc_handle&openid.sig=EEykK3fO58QFMzBBouu3Y8m3tCM%3D
```

```bash
# url
https://api.caseit.net/auth/external/telegram/login/callback?code=SJ0HxUX7zDbZpy14NXOyNygg5ZU&state=adKhOHbybDQWHdMmxQZwwA
```

#### Responses

```jsonc
// 200
"LzK2b2423v1sj3HU1zhXu_wJYOlsYt5wzl5mm_8_BD4"
```

#### Description

This endpoint checks authentication parameters and returns code if everything
is alright.

Different external providers may require different parameters to validate (e.g.
Steam uses legacy OpenID 2.0 (2026-07-11); Telegram previously used custom
web-login, but now uses OIDC; some authentication providers may use something
else).

Usually this endpoint is accessed when external authentication providers
redirect with 302 Found.

#### Parameters

As already stated, different external providers may require different
parameters to validate. E.g. OIDC providers redirect user with `code` and
`state`; OpenID 2.0 requires various parameters starting with "openid_..." like
`openid_sig`, `openid_nonce`, `openid_ns`. Parameters depend on provider and
authentication protocol it uses.
